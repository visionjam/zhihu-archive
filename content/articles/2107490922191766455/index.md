2026 年 11 月中旬，我给自己搭了一个叫 ASRTTS 的东西。名字是把 ASR（语音识别）和 TTS（语音合成）硬拼在一起，读起来像某个开源项目，其实就是我电脑和手机上的一个文件夹。

它只干两件事，方向相反：

* 把声音变成文字：一段录音、一期播客、一份现成字幕，进去，出来是可检索的 Markdown。
* 把文字变成声音：一篇文章进去，出来是带字幕、带章节的 m4a。

两条线共用一个投递口、一个输出目录、一个 API Key、一份账单。到写这篇为止它只跑了几天，产出不多，但该踩的坑基本踩了一遍。下面写的是我怎么用它，不是它有多厉害。

### 一、为什么是两个方向

我听播客有个老毛病：听完觉得「这期不错」，过两周只记得「不错」，具体讲了什么、数据是多少、哪句话值得引用，全没了。想回头找，只能拖进度条；一期二十多分钟的节目找一句话，比重新听一遍还慢。或者就是遇到一篇好长文好博客，实在没有时间和地点安静看完，就想能不能弄成播客，通勤路上听。

反过来是另一个毛病：走路、洗碗、等车的时候，脑子里经常冒出一段还算完整的想法。掏出手机打字，打完那段想法已经凉了；用语音备忘录录下来，录完就再也没打开过。

这两件事看着无关，其实是同一件事：声音和文字之间没有一条顺手的路。要么听完就散，要么录完就沉。

ASR和TTS 就是把这两条路铺上。

### 二、它长什么样

一个目录，两个技能。目录结构是这样：

```
ASRTTS/
├─ 00-Inbox/
├─ agent-skill/
│  ├─ asr-notes/
│  └─ tts-cast/
├─ archive/
├─ inbox/
├─ logs/
├─ out/
│  ├─ 2026-11-18-xxx/
│  │  ├─ index.md
│  │  ├─ transcript.md
│  │  ├─ cleaned.md
│  │  └─ notes.md
│  └─ daily/
├─ tests/
├─ windows/
├─ work/
├─ README.md
├─ 播客说明.md
├─ 同步说明.md
├─ 助手说明.md
├─ config.env
├─ cast-find.sh
├─ check-sync.sh
├─ stignore.template
├─ 一键处理.sh
├─ 一键处理.cmd
├─ 一键开播.sh
├─ 一键开播.cmd
├─ 自检.cmd
└─ ASRTTS.cmd
```

| 路径 | 是什么 |
| --- | --- |
| inbox/ | 投递口：录音、字幕、文章都丢这里，各自认领 |
| out/ | 一条一个文件夹：录音稿是四个 md，播客是 m4a 加三种字幕 |
| archive/ | 处理完的原件，唯一的原始凭证 |
| work/ | 切片缓存，重跑时省一次钱 |
| 00-Inbox/ | 一句话的碎片，按天一个文件 |
| agent-skill/ | 两个技能的代码与提示词，不跟数据混在一起 |
| windows/ | Windows 壳，只管编码、路径和参数转发 |
| logs/ | 壳的运行日志，不同步 |
| config.env | Key，不同步、不提交 |

播客和录音稿共用 `out/`，靠 `index.md` 里的 `type` 区分（`cast` / `voice-index`）。手机上这个目录和 PC 上是同一份，靠 Syncthing 双向同步。

目录模板和两个技能的代码我放在 [visionjam/ASR-TTS](https://github.com/visionjam/ASR-TTS)：仓库里只有结构和脚本，录音、文稿、Key 和本地那几份说明都没有上传。

「技能」是给 agent 读的说明书加脚本（SKILL.md 加 Python）。所以用法不是点按钮，是说话或敲一行命令：手机上一句「把 inbox 里的处理了」，PC 上双击一个 `.cmd`。底层是同一套 Python。

我特意没找现成的 App。装一个 App 意味着再维护一个 App：登录、更新、权限、付费、某天停服。文件系统加脚本不会停服，十年后还能跑，哪怕 agent 换了三代。

### 三、声音变成文字

接口有个硬限制：单次只收 120 秒以内、8 MiB 以内的音频。所以长录音必须先切。脚本用 [ffmpeg](https://ffmpeg.org/) 解码，按静音挑切点，逐片上传，再拼回来。

23 分 35 秒的一期播客，切成 14 片，一两分钟跑完，转写费 0.153 元。

一条录音出一个文件夹，四个文件：

| 文件 | 是什么 | 什么时候看 |
| --- | --- | --- |
| index.md | 元数据卡片加双链 | 在库里扫一眼 |
| transcript.md | 逐字稿，ASR 原样 | 核对某句话到底怎么说的 |
| cleaned.md | 清洗稿，去口水词、修同音字 | 快速通读 |
| notes.md | AI 结构化稿 | 拿去用、发给别人 |

分开的理由很实际：改整理模板不用重新转写。重跑一次结构化大约三分钱、八秒；整条重来要再付一遍转写费。手改了逐字稿里的错字再重跑，AI 读的是你改过的版本，不是它自己那份。

### 摘引是真核对过的

`notes.md` 里每条论点后面会跟一个 `[原话]` 或 `[归纳]`。

机制不复杂：提示词要求模型每条附一句从原文逐字复制的话，脚本拿这句话去原文里找。整句连续命中，保留引文，标 `[原话]`；找不到（模型改写了，或者把前半句和后半句拼在一起），删掉引文，降级成 `[归纳]`，并在日志里报一句。

这个护栏是被现实逼出来的。早期只靠机械判据——正文里有没有一段连续 60% 能在原文里找到——在一期播客上，七条论点全被判成 `[归纳]`。模型必然转述，比例阈值必然不达标，「可直接引用」等于没有。现在模型负责摘，脚本负责验，验不过就删。

所以引用的时候只引括号里那句，别引整条。论点本身可能还是模型转述的。

### self 和 external 是两套模板

自己口述的录音，模板关心「我想清楚没有、下一步做什么」；别人的播客、讲座，模板关心「他说了什么、有没有论据、以后怎么查」。

后者不输出「下一步」「还没想清楚的地方」——讲话人不是你，那两栏等于替别人做自我检讨。它多出来的是「论据与数据」「广告与赞助」「值得回听的段落」「提到的人 / 书 / 事」。

来源由我说，不从文件名猜。这条写进了技能说明里，因为猜错一次，整篇稿子的角度就歪了。

### 一个具体例子

我拿马督工那期[《睡前消息 1132》](https://www.bilibili.com/video/BV1Kqsr6xEep/)试的：23 分 35 秒，14 片，转写 0.153 元。

出来的整理稿里，前半段关于高尔夫球场整顿的论证被拆成五条，每条都带原话；后半段萨尔瓦多出兵海地，数据被单独抽成一节：「萨尔瓦多人口约 600 万，海地约 1200 万」「太子港 80% 城区被黑帮控制」「2024 年帮派暴力致 5601 人死亡」。这些东西我听完一遍绝对记不住，现在搜「5601」就能回到那一期。

广告也没混进来：整理稿里只列 `[18:25]` 萌牙家冲牙器、`[22:05]` 萌牙家电动牙刷，不复述文案、不引价格。广告里的销量和好评率不许写进「论据与数据」——否则一半的「数据」都是口播话术，检索的时候全是噪音。逐字稿里广告原样保留，折叠只发生在 AI 稿。

### 已经有字幕的，不重复花钱

如果手上已经有 srt、vtt 或 ass，就不该再转写一遍（从哪来，下一节说）。丢进去走 `--srt`，产出还是那四个文件，只是清洗稿不调模型——人工字幕的标点和断句通常比模型好，拿模型去「洗」只会把它改坏，还白花一次调用。

自动字幕（视频平台那种滚动式的）要先砍重叠，不然每句会出现两三遍。这个脚本自己处理。

### 四、字幕和音视频：yt-dlp 那一层

ASRTTS 只认已经存在的字幕文件。从 URL 到 srt 这一段它不管，那是 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 的活。

手机上我用 [YTDLnis](https://ytdlnis.org/)（开源在 [GitHub](https://github.com/deniscerri/ytdlnis)），Windows 上用 [YTDownloader](https://github.com/aandrew-me/ytDownloader)。两个都是 yt-dlp 的图形壳：界面里点格式、点字幕，底下拼的还是同一条命令。壳省掉的是记参数，省不掉的是「底下到底在干什么」——换平台、换机器的时候，参数还是得自己看一眼。

### 先看有什么，再挑

```
yt-dlp --list-subs "视频地址"
```

YouTube 的英文轨有 `en`、`en-US`、`en-orig`，中文有 `zh`、`zh-Hans`、`zh-Hant`；B 站的 AI 字幕是 `ai-zh`、`ai-en` 这种带前缀的。别背代码，先列一遍。

### 英文字幕

这是我在手机上跑的那条：

```
yt-dlp --skip-download \
  --write-subs --write-auto-subs \
  --sub-langs "en.*,ai-en" \
  --convert-subs srt \
  --cookies /data/data/com.deniscerri.ytdl/cache/cookies.txt \
  -P /storage/emulated/0/Download/YTDLnis/Command \
  -o "%(title)s.%(ext)s" "视频地址"
```

逐项拆开：

| 参数 | 作用 |
| --- | --- |
| --skip-download | 只下字幕，不碰视频 |
| --write-subs | 人工字幕 |
| --write-auto-subs | 自动字幕 |
| --sub-langs | 要哪些语言，逗号分隔，支持正则（区分大小写） |
| --convert-subs srt | 统一转成 srt，YouTube 默认给的是 vtt |
| --cookies | 登录态，见下 |
| -P / -o | 输出目录 / 文件名模板 |

`--sub-langs "en.*,ai-en"` 里，`en.*` 是正则，匹配 `en`、`en-US`、`en-orig` 这些变体；`ai-en` 是 B 站那种 AI 英文字幕。两个都得列——正则不跨前缀，`en.*` 匹配不到 `ai-en`。

### 中文字幕

只换语言那一行，其余照抄：`--sub-langs "zh.*,ai-zh"`。

`zh.*` 覆盖 `zh`、`zh-Hans`、`zh-Hant`、`zh-CN`、`zh-TW`；`ai-zh` 是 B 站的 AI 中文字幕。只要简体就写 `zh-Hans,ai-zh`，别用 `zh.*` 把繁体一起拖下来。

常用代码：

| 要什么 | 写什么 |
| --- | --- |
| 英文全部 | en.\* |
| 简体 | zh-Hans |
| 繁体 | zh-Hant |
| 中文全部 | zh.\* |
| B 站 AI 中文 | ai-zh |
| B 站 AI 英文 | ai-en |
| 全都要 | all |

### cookie

有些东西没登录态拿不到：年龄限制、会员、地区限制，以及 YouTube 越来越常见的「确认你不是机器人」。没有 cookie 时常见的是 403，或者一句 `Sign in to confirm you're not a bot`。

桌面端最省事的是直接从浏览器读：

```
yt-dlp --cookies-from-browser firefox "视频地址"
```

`firefox` 换成 `chrome` / `edge` 也行。Chrome 系在浏览器开着的时候会锁 cookie 库，读不到就先关掉浏览器。

也可以导出一份 Netscape 格式的 `cookies.txt`，用 `--cookies cookies.txt` 指过去。

手机上更省事：YTDLnis 内置了 cookie 登录，在应用里登一次，它自己把 cookie 存到缓存目录；上面那条 `--cookies` 指的就是这份，命令执行器直接能用，不用手动导出。

cookie 等于账号凭证。别提交 git、别丢网盘、别放进同步目录；过期了就重新登一次（桌面端重新导一份）。这和 ASRTTS 的 `config.env` 是同一个道理。

### 视频

```
yt-dlp -f "bv*+ba/b" --merge-output-format mp4 \
  -o "%(title)s.%(ext)s" "视频地址"
```

`bv*+ba/b` 是「最好的视频加最好的音频，没有就退回单文件」。合并要 ffmpeg：两个图形壳一般都会帮你备好，命令行跑就得自己装。

只要 1080p 以内：

```
yt-dlp -f "bv*[height<=1080]+ba/b[height<=1080]" \
  --merge-output-format mp4 "视频地址"
```

### 音频

```
yt-dlp -x --audio-format m4a -o "%(title)s.%(ext)s" "视频地址"
```

`-x` 抽音频，`--audio-format` 转码。m4a 给 ASR 最省事，不用再换容器；mp3 兼容性最好。抽音频和转码都要 ffmpeg。

只想留原始音轨、不转码：

```
yt-dlp -f ba -o "%(title)s.%(ext)s" "视频地址"
```

拿到的是 opus 或 webm，ASR 之前还得 ffmpeg 转一次。所以除非你就是要原始音轨存档，否则没必要省这一步。

### 回到 ASRTTS

拿到 srt 丢进 `inbox/`，跑 `--srt`，剩下的就是第三节那条管线；音频同理，进 `inbox/` 走转写。

视频本身可以不下：有字幕就下字幕，没字幕才需要音频去转写。

Windows 上把 `-P` 和 `--cookies` 换成自己的路径，其余照旧；在 YTDownloader 里这些是设置项，不用手写。

两个壳的差别只在这层皮：YTDownloader 新版能直接查看它拼出来的 yt-dlp 命令，对着看两遍就会了；YTDLnis 的「命令」模式可以自己填参数，`-P` 指的那个 `Download/YTDLnis/Command` 就是它的命令输出目录。

### 五、文字变成声音

反方向的设计只有一句话：朗读的粒度是段，字幕的粒度是句，数据只有一份。

按段合成，整段一口气念下来，韵律连贯，不会像播报机一句一顿；按句出字幕，段内按字数比例插值时间，误差大约 ±0.3 秒，够定位、看着不出戏。srt、口播稿、元数据、m4a 里的章节，全部从同一张带时间的段落表渲染出来，改样式只改一个渲染文件。

一期产出五个文件：m4a（内嵌章节）、srt、lrc、`script.md`（带 `[mm:ss]` 的口播稿）、`index.md`。30 分钟的音频大约 13 MB。

### 先试音，再整篇

第一次做某篇，流程是三步：`--dry-run` 看几段、多少字、多少钱、多长，一分钱不花；`--preview 300` 只合成前 300 字，约一分钟、五分钱，产物落在单独的「试音」目录；听着满意再跑整篇。

这不是谨慎，是算过账。整篇烧完才发现音色不对或语速太快，那才叫浪费。

### 改一个字，只重烧那一段

`script.md` 是源。改完稿子从它重跑，没改过的段从缓存里复用，本次计费字符为 0。想全部重烧才用 `--resynth`，那个才花钱。

还有一个细节挺要紧：判断「这期做过没有」看成品，不看目录。目录在、里面既没有 m4a 也没有 `index.md`，说明上次建完目录、开烧之前被打断了，脚本会照常重做，不会把它当成已完成而跳过。

目录名就是这一期的身份。改稿时标题动了一个字，重跑仍然沿用原目录名，不会另起一炉、把整篇重烧一遍。

### 一个具体例子

我翻出观察者网 2016 年的一篇旧文[《李世石败了，要警惕人工智能吗？》](https://www.guancha.cn/MaPing/2016_03_09_353436_s.shtml)，七千多字。转成播客是 25 分 41 秒，累计花费 2.15 元。

那篇文章我自己是不会重读的：观点过时了一半，剩下的也懒得再逐字看一遍。但变成音频之后，通勤路上就听完了，听到某一段还能想「这里当年其实没想清楚」。

我也做过 A/B：同一段 315 字的稿子，[DeepSeek](https://www.deepseek.com/) 的 tide 烧出来 1 分 05 秒，[豆包](https://www.volcengine.com/product/doubao-voice) 的刘飞是 1 分 11 秒，各九分钱。结论是豆包音色多（170 多个）、能调语速；DeepSeek 只有两个音色、不能调语速，而且没有语调，也不好听。现在默认走豆包，语速调到 -20，不然偏快。

### 三种播放器，三种字幕

这个坑值得单独说，因为它不是 bug：

* [mpv](https://mpv.io/) 认同名的 `.srt`，同名自动加载；
* 安卓本地音乐播放器（[Pixel Player](https://github.com/PixelPlayerHQ/PixelPlayerOSS) 这类）把 `.lrc` 当歌词读，不认 srt；
* 播客 App（[AntennaPod](https://antennapod.org/) 之类）只认 m4a 里内嵌的章节；
* [VLC](https://www.videolan.org/vlc/) 对纯音频默认不建视频输出窗口，srt 没有地方画，所以不显示——开可视化就有了。VLC 也不解析 lrc。

![image](./a3b686e895caea52.jpg)

*Pixel Player 读同名 .lrc：播客放到哪句，歌词跟到哪句。这期是《李世石败了，要警惕人工智能吗？》。*

所以两种字幕都生成，谁认哪个用哪个。为省一个文件只生成一种，最后一定是在某个播放器上抓瞎。

### 六、把它接成一个圈

两条线单独用都只是工具，接起来才有点意思。

别人的播客 → 转写 → 整理稿里挑出论点 → 自己重写一版口播稿 → 烧成播客。我拿《睡前消息 1132》的后半段试过一次：1115 字，3 分 43 秒，三毛钱。

这件事的意义不在省钱。听一遍不算消化，把它讲一遍才算。而「讲一遍」的成本是三毛钱、几分钟，门槛低到可以随手做。

反过来也成立：我把自己的口述转成稿，再让它读回来听。听自己说话，比看自己的文字更容易发现「这句其实没想清楚」。

### 七、两台机器，一份目录

手机负责录和丢，PC 负责跑和存。中间用 **[Syncthing](https://syncthing.net/)** 同步同一个目录：Android 端装 Syncthing-Fork，Windows 端装官方版，配对一次，之后两边各自改、各自收。免费、开源、不经过网盘，这是我一直用它而不是网盘同步的原因。

这套同步的取舍比想象中难：

| 路径 | 同步 | 原因 |
| --- | --- | --- |
| 分片缓存 chunks.json | 是 | 已经付过钱的转写结果，同步过去 PC 上重跑不用再付一遍 |
| 合成分段 wav | 是 | 同上，合成费 |
| merged.wav | 否 | 一期十几 MB，每次都能重算 |
| config.env | 否 | 里面是 Key，同步等于复制一份到另一台机器 |
| logs/ | 否 | 两端各写各的，同步必冲突 |

缓存这条我一开始写错了：整个目录排除，理由是「缓存可以重建」。后来想明白，重建就是重新转写——省下的是流量，花掉的是钱。现在只排除每次都能重算的大件和日志。

另外两条：一次只在一台机器上跑，两端同时跑会抢状态文件；批量改库里的文本之前先暂停同步，否则会落下 `*.sync-conflict-*` 副本，它不会自动清理，会一直混在目录里。

### Windows 那层壳

脚本本身是跨平台的，但 Windows 上有些麻烦必须单独处理，所以有一层壳，只做三件事：定位目录、强制 UTF-8、原样转发参数。

麻烦具体在哪：

* PowerShell 5.1 用 `Set-Content -Encoding UTF8` 写文件会加 BOM。ffmpeg 读到 BOM 会报 `unknown keyword 'file'`；Python 读配置时，第一个 Key 名前面会多一个看不见的字符。所以写配置必须走无 BOM 的写法。
* 路径里带中文和空格，所有命令都得加引号。
* 默认禁止运行脚本，双击的 `.cmd` 里带了绕过参数。

壳存在的理由不是「封装」，是这些坑每次都会重新踩一遍。双击一个 `.cmd` 比记住一长串命令现实得多。

### 手机上：RikkaHub 的共享文件夹

前面这些操作，在手机上原本要开好几个 App：录音机、文件管理器、聊天窗口、播放器。还要熟悉代码和配置环境。

现在只剩两步：把原始材料丢进Android的共享目录，在 [RikkaHub](https://rikka-ai.com/)（[GitHub](https://github.com/rikkahub/rikkahub)）里说一句「处理一下」。

RikkaHub 的工作区是个基于 proot 的 Linux 环境，能读写这个共享目录，也能跑技能里的 Python 和 ffmpeg。装好一次依赖，转写、整理、开播、抓字幕（yt-dlp 也能装进去）就都在同一个 App 里完成，产出直接落进 /out，不用在几个 App 之间来回倒。

这也是我把这套东西做成「目录 + 技能」而不是 App 的原因：换一个 agent，目录还是那个目录，命令还是那几条；换成 App，换一个就得重学一遍。

### PC 上：让 agent 代劳

PC 上同理，只是把「聊两句」换成「交给 agent」。Claude Code、Codex 这类工具能直接在工作目录里读 SKILL.md、跑 `一键处理.sh` / `一键开播.sh`；我这边用的是 DSH。先 `--dry-run` 估价，跑完把结果和花费报给你；失败了看 `work/error.log` 重试。

人剩下的事只有三件：决定做什么、审稿、听成品。搬运文件、记参数、算钱、重跑失败段，这些不该占注意力。

边界也得说清楚：付费命令（正式转写、正式开播）仍然要人点头；一次只在一台机器上跑；agent 能保证「跑完了」，保证不了「这篇值得听」。

工具链省下来的不只是钱，而是注意力。

### 八、钱

| 动作 | 花费 |
| --- | --- |
| 23 分钟播客：转写加整理 | 约 0.20 元 |
| 7000 字文章转播客 | 约 2.15 元 |
| 300 字试音 | 约 0.05 元 |
| 改稿重跑（只重烧改动段） | 0 |
| dry-run、自检、离线测试 | 0 |

十块钱够转写大约 25 小时。转写是 0.39 元一小时（限时五折，原价 0.78），整理约 0.05 元一万字。

播客这边两家其实一样贵。把计费口径折算成「元每万汉字」，DeepSeek 和豆包都是 3.0——DeepSeek 按两个字符算一个汉字，豆包按一个字符算一个汉字，单价差一倍，折算完打平。区别在音色和语速。而且 DeepSeek 的五折是 2026 年内的，明年回原价，豆包反而便宜一半。这种事不该写死在脚本里，所以供应商是个配置项。

护栏有三条：`--dry-run` 一定免费（连改写都不发出去）；单次预计超过一块钱先停一下；`index.md` 同时记「本次」和「累计」，重跑不会把已经花掉的钱抹成 0.00。

### 九、它没解决的

* 没有句子级时间戳。逐字稿里的 `### mm:ss` 是分片起点，大约两分钟一个，够回听，做不到逐句对齐。字幕模式例外，cue 本身就是精确时间。
* 不支持流式，必须整片上传后等结果。
* DeepSeek 不能调语速。书面语偏快或偏慢，只能靠改稿时的标点密度调。
* 内容审核不过的段会被跳过，不扣钱，记在 `index.md` 里。整批不会因此中断，但那一段就是没有。
* AI 稿仍然要人读一遍。它的价值是把九十分钟压到十分钟，不是替你做判断。摘引核对只能保证「这句话是原话」，保证不了「这个论点成立」。
* 抓字幕不归它管，那是 yt-dlp 的活，见第四节。
* 同时只能一台机器跑。

最大的限制其实不在上面这些：它不解决「值不值得听」。管线再顺，垃圾进还是垃圾出。

### 十、我现在的用法

* 通勤路上听自己烧的播客。听到一句想记的，回来 grep 字幕拿到时间戳，跳回去重听那三十秒。
* 路上口述几分钟，晚上跑一条命令。第二天早上读清洗稿，比读自己的语音转文字舒服得多。
* 碎片用 `--add` 记一句，晚上 `--daily` 聚合成日结。日结里最有用的不是「要点」，是「还悬着的」——说了半句、自己也没结论、前后矛盾的话，原样留着。第二天早上看见昨天卡在哪，比看见昨天干了什么有用。
* 旧文隔一段时间挑一篇烧成音频，当作重读。

### 十一、最后

这套东西没有多聪明。它只是把「想记」和「记下来」之间、「想听」和「有得听」之间的几步路铺平了。铺平之后我才发现，真正稀缺的不是工具，是愿意对着手机说五分钟话的那个时刻，和愿意把一篇旧文重新读一遍的那个下午。

所以我不建议照抄这套目录。我建议先找一件每天都会发生、但每次都要多花三分钟的小事，把它接成一条管子。ASRTTS 只是我的那根。
